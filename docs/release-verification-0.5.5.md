# 0.5.5 房间生命周期与大厅布局验证记录

验证时间：2026-07-26 08:00:55 +08:00

验证分支：`develop`

应用版本：`0.5.5`

协议版本：`4`

桌面设置 schema：`6`

## 用户可见修复

1. 实际主机可在桌面“联机”面板确认关闭当前房间。服务器会销毁该房间、移除全部
   session、停止采集并以 WebSocket 关闭码 `4004` 向每名在线玩家发送明确原因。
   主机和访客都会停止无意义的自动重连、清除旧会话并返回主界面；内置服务保持运行，
   可立即创建下一间房。
2. 大厅不再显示占据整行的黄色 `INVITE PLAYERS` 房间码横幅。六位房间码改为顶栏
   左上角品牌区域中的紧凑按钮，所有房内用户点击该房间码即可复制。
3. 关闭主窗口默认退出整个应用，不再默认最小化到托盘。设置 schema 从 5 升级为 6；
   旧安装会一次性把历史默认值迁移为关闭即退出，之后只有用户主动开启“保持在托盘
   运行”才会拦截窗口关闭。

游戏 JSON / 二进制消息 schema 没有变化，因此 `PROTOCOL_VERSION` 继续保持 `4`。
房间终止使用既有 `error` 消息以及既有的私有 WebSocket 关闭码，不要求 v4 客户端
解析新的消息类型。

新增或扩展的自动化覆盖：

- 非法实际主机控制密钥无法关闭房间；
- 关闭房间后房间、session 和在线 socket 被清理，主机与访客均收到“房主已关闭房间”；
- 桌面客户端把关闭码 `4004` 识别为终止状态并清除会话，不进入重连循环；
- 浏览器客户端的同一关闭码处理路径会清理快照、停止重连并在首页保留关闭原因；
- schema 5 中的旧托盘默认值会迁移为 `false`，schema 6 中用户之后的明确选择会保留；
- 紧凑房间码组件仍提供可访问的复制按钮，不包含旧邀请横幅内容。

打包应用 smoke 实际执行并确认：

1. 自动启动内嵌服务并创建房间；
2. 六位房间码位于顶栏且控件本身是按钮；
3. 旧 `.host-room-code-banner` 不存在；
4. “联机”面板同时显示修改密码与关闭房间操作；
5. 点击关闭房间后主界面恢复，左上角房间码消失；
6. 已关闭房间的加入接口返回 `404`；
7. 内置服务仍为 `running`，无需重启即可重新开房；
8. 新设置和从 schema 5 迁移后的设置均以“关闭窗口即退出”为默认行为。
