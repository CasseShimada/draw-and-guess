协议版本：`4`

## 用户可见修复

1. 实际主机进入房间后，可在桌面“联机”面板输入两次新密码并更新当前房间密码。
   旧密码不回显、不进入房间快照、桌面设置、剪贴板或诊断日志。更新成功后，旧密码
   无法再加入，新密码立即生效，已经在房间内的会话保持在线。
2. 服务器为每个玩家分配房间内唯一、稳定的 `#四位数字` 昵称后缀。同名玩家可以
   加入，玩家列表、聊天、游戏过程和结算继续使用同一个服务端显示名。
3. 桌面加入失败会区分连接预检、切换服务器、验证房间、校验响应和建立实时连接，
   并同时显示原因与处理建议。首页加入错误保持显示到下一次提交；“诊断”页面突出
   显示最近一次加入失败的脱敏记录。
4. `ECONNREFUSED` 文案改为“目标地址的该端口拒绝连接”，并说明服务未启动、端口
   填错或只监听本机等可能原因，不再笼统声称“目标机器可达”。

游戏线上消息 schema 没有变化，因此 `PROTOCOL_VERSION` 继续保持 `4`。

新增或扩展的自动化覆盖：

- 同名玩家可加入，昵称均符合 `昵称#0000` 格式，后缀不会冲突且重连后保持稳定；
- 非法主机控制密钥不能修改密码；
- 修改密码后旧密码被拒绝、新密码成功加入，原房主会话继续有效；
- 连接拒绝与密码错误分别生成明确提示、阶段、错误码和建议；
- 加入诊断不含提交的昵称或密码；
- 401、404、409、403、429、500、响应 schema 错误和网络中断均有分类建议；
- IPC 仍由受信任 Renderer、严格输入 schema 和实际主机控制密钥共同保护。

打包应用 smoke 实际执行并确认：

1. 自动启动内嵌服务并创建房间；
2. 大厅显示真实六位房间码；
3. 房主重新载入会话后，“联机”面板显示两个新密码输入框；
4. 通过实际 IPC 修改房间密码；
5. 旧密码加入失败，错误提示明确指出密码错误或已修改；
6. “诊断”页面突出显示同一条 `UNAUTHORIZED` 脱敏记录；
7. 新密码通过真实 HTTP 加入接口成功；
8. 两个使用相同基础昵称的玩家获得不同 `#四位数字` 后缀。
