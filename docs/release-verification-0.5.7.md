## 用户可见功能

1. 游戏进行中，只有当前房主能从顶部工具栏进入“房间设置”。该页面只是本地界面，
   不会把服务器切回大厅，也不会中断其他玩家、计时器或桌面采集。
2. 经典画猜、参考图临摹和绘画接龙共用同一套受控设置表单。打开设置后，普通快照
   不会覆盖未提交的草稿；房主变化或房间会话变化时，过期草稿会被自动丢弃。
3. “返回游戏”只关闭本地设置页面；草稿有修改时先确认，服务器状态不发生变化。
4. “应用并重启游戏”使用协议 v5 的单条 `game:restart` 命令。服务端依次冻结旧局、
   撤销采集授权、处理接龙未完成回放、应用新设置、轮换会话并启动新局，其他玩家只
   接收最终一致状态。
5. 重启保留房间、房主、玩家、聊天记录和已配置内容资源；清空当前轮次、分数、计时
   器和旧采集授权。旧会话、旧轮次及旧采集数据都会被拒绝。
6. 新设置不满足开局条件时，旧局仍然终止，但房间会安全停在大厅空闲态并保留新设置
   与内容资源，同时向玩家显示明确错误；不会恢复出一个半旧半新的游戏。
7. 绘画接龙存在未完成录制时，重启与切换模式共用“保存后继续 / 丢弃后继续”的处理
   路径，避免产生孤立编码任务或残留文件。

新增或扩展的自动化覆盖：

- 浏览器和桌面协议均接受合法 `game:restart`，拒绝缺少命令 ID、模式与设置不匹配及
  数值越界的消息；
- 非房主、过期会话和模式不匹配的重启被拒绝，暂停中的房主仍可原子重启；
- 重复 `commandId` 不会二次重启，旧计时器、旧玩家操作和旧采集包无法污染新会话；
- 开局失败回退到安全大厅，玩家、设置和内容资源保留，计时器全部清理；
- 参考图重启后继续保留当前参考素材；
- 接龙重启必须明确处理未完成回放，保存与丢弃路径都复用已有回放收尾逻辑；
- 本地设置草稿在同一会话快照间保持，在房主或会话变化时失效；
- 设置页展示房间码、玩家列表、游戏仍在进行的警告、内容资源只读说明以及返回、
  恢复和重启操作，并且没有发送旧的 `game:return-lobby`。
