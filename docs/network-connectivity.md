# 网络联机与单端口转发

状态：`0.5.0` 当前用户与维护者说明。应用版本 `0.5.0`，游戏 WebSocket 协议版本
仍为 `4`，桌面设置 schema 为 `5`。

## 三种连接拓扑

### 仅本机

```text
房主 Electron
  ├─ Fastify 监听 127.0.0.1:<固定端口>
  └─ 房主游戏客户端连接 http://127.0.0.1:<同一端口>
```

此模式适合单机检查。`127.0.0.1` 和 `localhost` 永远指向“正在输入地址的那台电脑”，
不能发给其它玩家。

### 同一局域网

```text
房主 Electron
  ├─ Fastify 监听 0.0.0.0:<固定端口>
  ├─ 房主自己仍连接 127.0.0.1:<固定端口>
  └─ 其它设备连接 房主私有IPv4:<固定端口>
```

`0.0.0.0` 表示进程监听所有 IPv4 网卡，只用于诊断。玩家必须输入房主选择的具体
IPv4，例如 `192.168.1.20`。应用会列出网卡名称、IPv4、CIDR/子网掩码，并把 RFC1918
私有地址排在前面，但不会擅自隐藏 Hyper-V、WSL、Docker、VMware、VPN、Tailscale
或 ZeroTier。房主应选择与玩家真正相通的网络。

### 公网端口转发

```text
公网玩家
  │ 外部主机名:外部端口
  ▼
SakuraFrp / 受控反向代理
  │ 一个 TCP 转发
  ▼
房主 127.0.0.1:<实际本地端口>
  ├─ HTTP API 与浏览器入口
  ├─ WebSocket Upgrade 与控制消息
  └─ 二进制图片帧
```

应用不把游戏拆成多个媒体端口。HTTP、静态网页、WebSocket、聊天、控制和图片帧始终
复用一个 TCP 端口。外部端口与本地端口可以不同，例如公网 `45678` 转到本机
`3000`。

“像 Minecraft 一样”只表示玩家输入主机和端口、隧道只转发一个端口；游戏仍使用
HTTP + WebSocket，不使用 Minecraft 协议。

## 房主：启动固定端口服务

1. 打开桌面应用底部的“联机”。
2. 输入固定 TCP 端口，范围为 `1..65535`。
3. 选择绑定模式：
   - “仅本机”实际监听 `127.0.0.1`；
   - “局域网 / 可做端口转发”实际监听 `0.0.0.0`。
4. 点击“启动房间服务”。
5. 若端口被占用，应用会直接失败。关闭占用程序或明确换端口；应用不会静默搜索后续
   端口。
6. 创建房间后，在“玩家连接信息”中选择正确网卡。
7. 逐字段复制地址、端口、房间码，或复制普通文本连接信息。复制内容不含密码、
   session、query 或可点击深链。
8. 通过其它可信渠道单独告诉玩家房间密码。

服务运行时可以编辑端口或绑定模式草稿，但权威状态不会变化。点击“重启服务以应用”
前应用会说明当前房间和全部连接将结束。界面显示的实际监听地址、实际端口和服务实例
ID 始终来自主进程，而不是表单草稿。

网络变化后应用会重新枚举 IPv4；也可手动点击“重新枚举”。若上次选择的地址消失，
必须重新选择。`169.254.0.0/16` 是链路本地地址，通常不适合普通家庭路由器网络。

## 桌面玩家：地址 + 端口加入

在“加入房间”页填写：

```text
服务器地址或 IP
端口
连接安全性（HTTPS/WSS 或 HTTP/WS）
房间码
昵称
房间密码
头像（可选）
```

地址框是普通文本，支持：

```text
192.168.1.20              + 端口 3000
192.168.1.20:3000
http://192.168.1.20:3000
draw-host.local:3000
example.com               + 端口 443 + HTTPS
https://example.com:443
```

私有 IPv4、loopback 和 `.local` 默认选择 HTTP/WS；公网主机默认选择 HTTPS/WSS。
完整 URL 中的 scheme 或端口会同步到对应字段。若地址中的端口与端口框冲突，界面会
要求明确选择一个，不会静默猜测。

“测试连接”和直接“加入房间”都执行同一个主进程预检：

1. 严格规范化主机、端口和安全模式；
2. 在四秒限制内无凭据请求 `/api/connection-info`；
3. 不携带 Cookie、Authorization、房间码、密码或旧 session；
4. 不跟随 redirect，响应最多 16 KiB；
5. 校验 JSON content type、服务名、协议版本和固定 schema。

成功加入后才会写入最多八条“最近连接”；相同规范化 origin 会去重，用户可删除。
更改目标会关闭旧 WebSocket、取消旧请求和重连 timer、清除旧内存 token，再连接
新目标。旧服务器迟到的响应不会覆盖新界面。

本版保证 IPv4 和 DNS 名称。IPv6 输入会得到“0.5.0 暂不支持”的明确提示；应用不会
先接受再在绑定或连接阶段含糊失败。

## 浏览器玩家

浏览器版没有服务器地址框，因为当前页面的 origin 就是服务器：

1. 在浏览器地址栏手动输入房主提供的 `http://私有IPv4:端口`，或公网
   `https://主机:外部端口`；
2. 打开页面后输入房间码、昵称和密码；
3. 创建或加入后地址栏不会增加房间码；刷新恢复依赖同源 HttpOnly session Cookie。

浏览器 WebSocket 只接受同源 Origin，或服务端明确配置的精确公网 origin。应用不会
启用 wildcard CORS，也不会把整个局域网网段当成可信身份。

## SakuraFrp 设置边界

应用内的“公网分享信息”只保存：

- 外部主机名或公网 IP；
- 外部端口；
- HTTPS/WSS 或 HTTP/WS；
- 可选显示名称。

应用不会保存 SakuraFrp 账号、token、隧道 ID、后台密码、路由器凭据、房间密码或
桌面 session，也不会下载或启动 `frpc`。

推荐步骤：

1. 房主以“局域网 / 可做端口转发”模式在固定本地端口启动服务。
2. 若 `frpc` 与房主应用在同一台电脑，把本地目标设为
   `127.0.0.1:<实际本地端口>`。
3. 若 `frpc` 在另一台局域网设备上，把目标设为房主选定的私有 IPv4 和同一端口。
4. 把 SakuraFrp 给出的外部主机名和外部端口保存为“公网分享信息”。
5. 公网桌面玩家在加入页输入该外部主机、外部端口和正确安全模式。
6. 公网浏览器玩家手动打开对应 `http://` 或 `https://` 地址。

更改公网展示信息不会重启游戏服务。只有本地监听端口或绑定模式改变才需要重启。

## 原始 TCP 与 HTTPS 入口

### 原始 TCP 转发

公网入口把 HTTP 和 WebSocket 字节原样转发到本地端口。玩家选择 HTTP/WS。第一次
连接每个规范化公网 endpoint 前，桌面应用会显示不可忽略的风险说明：

- 房间密码、聊天和图片是明文；
- session 可能被链路上的第三方读取或篡改；
- 只应在理解风险并信任链路时继续。

确认与完整 origin（主机、端口、HTTP）绑定。更换主机或端口需要重新确认。

### HTTPS/WSS 反向代理或隧道

公网侧终止有效 HTTPS/WSS，再代理到本机 HTTP/WS。代理必须：

- 提供受客户端信任且与公网主机名匹配的证书；
- 转发 WebSocket Upgrade 和长连接；
- 保留正确 Host，或让服务端明确配置精确公网 origin；
- 只从明确可信的代理来源提供 `X-Forwarded-Proto/Host`。

服务端不把 Fastify `trustProxy` 无条件设为 `true`。只有可信代理地址和明确允许的
HTTPS origin 同时匹配时，浏览器 session Cookie 才添加 `Secure`。局域网直接 HTTP
仍使用非 Secure Cookie，否则浏览器无法保存 session。

TLS 失败只报告证书或握手问题。应用不会设置 `rejectUnauthorized: false`，不会接受
自签名证书绕过，也不会自动回退 HTTP。用户可以独立改选 HTTP/WS，随后仍需完成
明文风险确认。

## Windows 防火墙

监听 `0.0.0.0` 只证明进程接受网卡连接，不代表 Windows Defender 防火墙已经允许
入站流量。

- 首次出现系统授权提示时，建议只允许“专用网络”；
- 联机中心显示当前应用可执行文件、实际 TCP 端口和绑定地址，便于在系统设置核对；
- “打开防火墙设置”只打开固定的 Windows 设置入口；
- Renderer 不执行 PowerShell、`netsh`、shell 或任意系统命令；
- 应用不静默提权，不自动创建全局防火墙规则。

macOS 用户应在系统“网络/防火墙”设置中允许应用接收入站连接。Linux 用户应按发行版
防火墙工具允许当前 TCP 端口。应用无法绕过企业策略、访客 Wi-Fi 隔离、AP isolation
或路由器客户端隔离。

## 连接诊断

| 诊断 | 含义与检查 |
| --- | --- |
| 已找到兼容服务器 | 地址、端口、服务类型和游戏协议匹配。 |
| 地址或端口格式不正确 | 检查端口 `1..65535`、路径/query、userinfo、空白或不支持的 scheme。 |
| 无法解析服务器地址 | 检查主机名拼写、DNS、`.local` 支持和当前网络。 |
| 目标机器可达，但端口没有监听 | 房主服务或隧道未启动，或填错本地/外部端口。 |
| 请求超时 | 可能是错误 IP、防火墙、AP 隔离、路由问题或公网映射未生效，不等同于“防火墙一定阻止”。 |
| HTTPS 证书或 TLS 失败 | 检查证书主机名、有效期、信任链和隧道 TLS 配置；不会自动降级。 |
| 该端口不是画猜现场 | 端口返回网页、重定向或其它 JSON 服务。 |
| 协议不兼容 | 客户端与服务器游戏协议版本不同，需要统一升级。 |
| 公网明文尚未确认 | 明确阅读风险后确认该 endpoint，或改用 HTTPS/WSS。 |

常见错误：

- 把 `127.0.0.1`、`localhost` 或 `0.0.0.0` 发给另一台电脑；
- 选择了 WSL、Docker、VPN 等不与玩家互通的网卡；
- 房主填写的端口被其它程序占用；
- 玩家误把本地端口当成 SakuraFrp 外部端口；
- HTTPS 证书不匹配，或代理没有转发 WebSocket Upgrade；
- Windows 只允许了“公用网络”以外/以内的错误 profile；
- 双方位于访客 Wi-Fi、不同 VLAN，或路由器启用了 AP isolation；
- 隧道进程已停止，但房主误以为应用能自动恢复公网入口。

主机自检只证明本机进程监听且本机可访问。只有另一台设备成功完成预检、加入、
WebSocket 重连和图片接收，才能称为跨设备可达。

## 明确不做的事

0.5.0 不实现：

- 自动公网 IP 探测、UPnP、NAT-PMP 或路由器配置；
- 云中继、匹配服务器或 WebRTC；
- SakuraFrp 安装、下载、登录、token 管理或隧道控制；
- 第二个媒体端口、视频推流或笔画同步；
- TLS 错误绕过、wildcard Origin/CORS 或局域网身份信任。
